# SlideCheck Helper: decisions made during implementation (2026-10-01)

These decisions came from the helper plan's document review and the U1 spike (`docs/plans/2026-10-01-2113-feat-slidecheck-helper-plan.md`). Where this note and the plan differ, this note wins. Evidence is in `docs/notes/office-js-platform-behavior.md` under "Helper plan U1 gate".

- H1. **Certificate validity is 825 days or less in total, counting any backdating** (replaces the 10-year leaf in KTD2 and U6). macOS rejects longer leaves even under an admin-trusted root. Renewal happens through re-trust: when fewer than 90 days remain, `/v1/health` reports it and the pane tells the user to reinstall or approve renewal.
- H2. **Managed Macs: one approval per machine** (user decision; changes R7, KTD3, U8). Jamf installs the helper silently, but macOS refuses to trust a certificate from a root process with no user session. At the user's first login the helper asks once for an administrator's approval to trust its certificate. Until approved, the pane treats the helper as present but not trusted, and falls back to the show-machine list. Interactive installs keep a single prompt: the installer's own.
- H3. **Windows updates on unmanaged PCs are notify-only** (user decision; changes the Windows part of KTD5 and U7). Delivery works as in H5: the pane offers the update and the user runs the new installer, which shows UAC. Intune-managed PCs update through Intune.
- H4. **The leaf can never sign certificates:** critical `CA:FALSE`, key usage `digitalSignature` only, EKU `serverAuth`. The constrained root has `pathlen:0`. Verified in the U1 spike.
- H5. **Mac updates are notify-only too, and the helper never downloads or runs installers** (resolves OQ1 with the plan's fallback; follows H3). The helper checks the signed feed (minisign, newer version, HTTPS URLs only) and reports `update: {version, page}` in `/v1/health`. The pane offers "Helper update available", which opens the download page with `openBrowserWindow`. There is no root updater daemon, no drop folder and no privileged handoff. MDM-managed machines turn checks off (`AutoUpdate=false`) and deploy new versions themselves.
- H6. **Fonts are read from the font files themselves on both platforms** (narrows KTD6). Every face is parsed with ttf-parser for name IDs 1, 16 and 21. That includes the legacy family names, such as "Segoe UI Semibold", that decks store. On Mac, CoreText supplies the list of installed font files. On Windows, until DirectWrite lands after the U2 spike, the helper walks `%WINDIR%\Fonts` and the per-user fonts folder. Both platforms add the Office private and cloud folders, including the `Program Files (x86)` Office folder.
- H7. **Reviews usually happen on the show machine** (user decision; confirms KTD9 as planned). With the helper running, "Missing on this computer" (`font-missing-here`) is the primary font problem. The show-machine-list finding drops to a note. Without the helper, today's behavior stays.
